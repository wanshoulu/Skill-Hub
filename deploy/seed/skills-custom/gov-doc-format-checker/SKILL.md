# 党政机关公文 Markdown 格式检查器

## 适用场景与触发条件

**适用：**
- 用户提供一份 Markdown 格式的公文类文档（通知、请示、报告、函等），要求检查其格式与内容是否符合 GB/T 9704《党政机关公文格式》。
- 用户要求对公文 Markdown 进行规范化、自动修正。
- 用户明确提到 GB/T 9704、公文格式、公文规范、党政机关公文等关键词。

**触发关键词：** 检查公文、校验公文、规范化公文、GB/T 9704、公文格式、公文规范、党政机关公文、公文 Markdown 格式。

**不适用：**
- 非公文类文档（如技术文档、学术论文、普通说明文）——本 Skill 的检查规则基于公文标准，不适用。
- 需���检查字体、字号、页边距、红头、版记等版式属性的场景——Markdown 无法表达这些属性，本 Skill 只能提示，不能修正。
- 需要依据 GB/T 7714（参考文献）或 GB/T 9704 之外的国标进行检查的场景。
- 非 Markdown 格式（Word、PDF、图片）的文档——需先转换为 Markdown 或改用其他工具。

## 输入与前置条件

**必需输入：**
- 一份 Markdown 格式的公文文档（文件路径或文本内容）。

**权限与工具：**
- 对目标文件所在目录的读写权限（用于生成备份和写回修正结果）。
- 文件读写工具（读取原文、写入备份、写入修正后文件）。

**前置确认：**
- 确认文档确为党政机关公文类型。若无法判断文档类型，先向用户确认，不要盲目套用公文规则。
- 确认运行环境已启用受限执行器（沙箱），工具与脚本必须在受限环境中运行；未隔离的环境不得用于生产发布。
- 确认已选定测试所用模型，并已准备包含触发用例与任务用例的测试集，用于验证加载行为与任务输出。
- 确认目标平台兼容性已通过：本 Skill 在所选规范配置下可正常导出，字段完整。

**运行前置校验清单（全部满足方可进入执行流程）：**
1. ���选定测试使用的模型。
2. 已准备包含触发用例（正例/反例）与任务用例的测试集。
3. 工具与脚本运行于受限执行器（沙箱）中，隔离已生效。
4. 目标平台兼容性检查通过，本 Skill 可正常导出且字段完整。
5. 若上述任一项未满足，不得宣称本 Skill 可用于生产，应先完成相应验证并停止自动修正。

## 执行流程

1. **前置校验**：逐项核对"运行前置校验清单"。若任一项未满足（未选定模型、未准备测试集、未启用隔离、兼容性未通过），停止执行并报告缺失项，不得继续修改文件。

2. **读取文档**：读取目标 Markdown 文件的完整内容，记录文件路径。

3. **创建备份**：在修改前，将原文件复制为 `<原文件名>.bak`（若已存在同名备份，追加时间戳，如 `<原文件名>.20260912.bak`），确保原文可恢复。

4. **检查结构要素**：核对公文必备要素是否齐全，包括：
   - 标题
   - 主送机关
   - 正文
   - 发文机关署名
   - 成文日期
   记录缺失项。

5. **检查层次序数**：核对正文层次序数是否符合规范层级与标点：
   - 第一层：一、二、三……（汉字数字 + 顿号）
   - 第二层：（一）（二）（三）……（括号内汉字数字，后不加标点）
   - 第三层：1. 2. 3.……（阿拉伯数字 + 下脚点）
   - 第四层：（1）（2）（3）……（括号内阿拉伯数字，后不加标点）
   检查是否存在层级跳级、序数标点错误。

6. **检查标点符号**：依据 GB/T 15834 检查中文标点使用，如顿号、引号、书名号、括号等是否规范，是否存在中英文标点混用。

7. **检查数字用法**：依据 GB/T 15835 检查数字使用，如公文中应使用阿拉伯数字的场合是否误用汉字数字，反之亦然。

8. **检查成文日期格式**：核对成文日期是否为"YYYY年M月D日"格式（如"2026年9月12日"），检查是否使用阿拉伯数字、是否规范。

9. **自动修正**：对第 5–8 步中**确定性**的问题直接修正（层次序数、标点、数字、成文日期格式）。对第 4 步的结构要素缺失，**不擅自增补内容**，仅记录并提示。

10. **写回文件**：将修正后的内容写回原文件。

11. **输出报告**：生成检查报告，包含：
    - 已自动修正的问题清单（问题位置、原内容、修正后内容）
    - 需人工处理的问题清单（结构要素缺失、版式类问题）
    - 备份文件路径

## 完成标准

- 前置校验清单全部满足，且已选定测试模型、已准备触发与任务测试集、隔离已生效、兼容性检查通过。
- 原文件已生成备份，且备份内容与修改前完全一致。
- 所有确定性格式问题（层次序数、标点、数字、成文日期）已修正并写回文件。
- 已输出完整检查报告，明确区分"已修正"与"需人工处理"两类问题。
- 报告中列出的版式类问题（字体、字号、页边距、红头等）已明确标注为 Markdown 无法处理。
- 不能仅以"已读取文件"或"已调用工具"作为完成依据，必须以报告产出和文件实际写回为准。
- 触发测试通过：正例能正确加载本 Skill，反例不误加载。
- 任务测试通过：真实输出、工具调用、耗时与禁止操作均符合用例要求。
- 兼容性检查通过：本 Skill 在目标平台规范配置下可正常导出，字段完整。

## 异常处理与安全边界

- **前置条件未满足**：若未选定测试模型、未准备触发与任务测试集、隔离未生效或兼容性未通过，停止执行并报告缺失项，不得宣称可用于生产。
- **文档类型不确定**：若无法判断文档是否为党政机关公文，停止自动修正，先向用户确认。
- **文件不可读写**：若无法读取或写入目标文件，停止操作并报告错误，不得在无备份的情况下修改。
- **备份失败**：若备份创建失败，**禁止继续修��原文件**，直接终止并提示用户。
- **规则冲突或不确定**：若某处修改存在多种合理解释（如数字用法在特定语境下可汉字可阿拉伯数字），**不自动修改**，列入"需人工确认"清单。
- **结构要素缺失**：不擅自编造或补全标题、署名、日期等内容，仅提示。
- **版式类问题**：字体、字号、行距、页边距、红头、版记等一律只提示，不尝试在 Markdown 中模拟。
- **高风险操作**：任何覆盖原文件的操作，必须确保备份已成功创建。
- **隔离要求**：所有工具与脚本必须在受限执行器中运行；未隔离的运行结果不得用于生产发布。
- **环境未就绪**：若未选定测试模型、未准备触发与任务测试集，或目标平台兼容性未通过，不得宣称本 Skill 可用于生产，应先完成相应验证。
- **禁止操作**：不得删除原文件、不得跳过备份、不得在未确认文档类型时执行自动修正、不得在未隔离环境中执行工具与脚本。
